[2026-04-19] CHANGE: Offline rule-based cleanup as fallback when GPT-4o-mini is unreachable. Problem surfaced during live testing: when the cloud Whisper call failed (triggering local faster-whisper fallback), the subsequent GPT cleanup call ALSO failed because it hits the same OpenAI infrastructure — so the user was pasted raw local Whisper output: fillers, duplicate words, run-on sentences, no sentence capitalisation. Fix: new _rule_based_cleanup() function runs entirely offline and strips classic fillers (um/uh/erm/mm/hmm), collapses immediate duplicate words ("the the" → "the"), collapses whitespace, capitalises standalone "i" plus common contractions (i'm, i'll, i've, i'd, i't), capitalises the first letter of each sentence, and ensures terminal punctuation. Deliberately conservative — does not remove legitimate speech patterns like "sort of", "basically", "like" (would mangle real sentences), and cannot fix misheard words (that's a model-quality issue; small.en local model is the v1.3 upgrade). cleanup_text() now calls GPT first; on any exception falls through to _rule_based_cleanup() instead of returning raw text. Log line [CLEANUP] distinguishes GPT vs rule paths ("cleaned by GPT-4o-mini in Xs" vs "GPT unavailable (err) — applying offline rule-based cleanup to N words"). Verified against Billy's actual 112.2s problem recording: output readable without GPT. | FILES: kaira.py, CHANGELOG.txt | RELEASED: no

[2026-04-18] CHANGE: Default activation mode flipped from hold-to-talk to tap-to-toggle for fresh installs. Cold first-run testing on two separate laptops (wife's Lenovo + a similar-spec machine) revealed the same UX trap: users instinctively tap Ctrl+Win — in hold-to-talk mode that looks like nothing happened, because microtransition suppression correctly cancels fast press+release events. Research (v1.2 brief) had recommended hold-to-talk as the market default (Wispr Flow, DictaFlow, Aqua Voice) but those products teach the gesture aggressively during onboarding. Kaira doesn't yet. Tap-to-toggle matches instinct out of the box. Users who prefer the walkie-talkie feel can flip in Preferences. Also: pre-v1.2 configs migrating through load_settings() now fill missing activation fields with "toggle" (was "hold_to_talk") so existing installs move with the product on next launch. Hover hint on the floating pill now reads the actually-configured hotkey via format_hotkey(cfg) instead of the hardcoded "Ctrl+Win" — custom hotkey bindings surface correctly. Tray tooltip uses format_hotkey(..., include_mode=True) so "(tap to toggle)" or "(hold to talk)" suffix appears. | FILES: kaira.py, CHANGELOG.txt | RELEASED: no

[2026-04-18] CHANGE: Local faster-whisper fallback on cloud failure. When Whisper API exhausts its retry budget (transient connection errors, timeouts, or 5xx bursts like the APIConnectionError seen during live testing today), Kaira now transcribes the same WAV locally using faster-whisper on the CPU — user never loses a recording to a network blip or OpenAI hiccup. Implementation: new module-level helpers `_local_fallback_available()`, `_get_local_model()`, `_transcribe_locally()` plus a `fell_back_to_local` widget signal. `transcribe()` tries cloud first; on RetryError it runs faster-whisper against the same WAV, sets `transcribe.last_used_local = True`, and returns. Pipeline (_transcribe_and_paste + _execute_voice_command) emits the signal after a successful local pass; tray shows an info toast "Kaira — used local fallback". Both cloud and local outputs pass through the existing Layer-3 hallucination-phrase blocklist. Model config: base.en, int8 quantized (~145 MB on disk), cpu_threads=4, stored in %APPDATA%\Kaira\models\ via faster-whisper's download_root; downloads lazily on first fallback use. Measured on Intel UHD 8GB: ~2.4x realtime transcription (106s audio → 252s CPU time); first model load ~80s including download. Also companion fix: tenacity decorator changed from reraise=True to reraise=False so RetryError actually wraps the final failure — without this, `except RetryError` never fired and errors silently fell through to the generic catch-all, bypassing dead-letter tracking and the outage toast. kaira.spec updated with collect_all() for ctranslate2, faster_whisper, tokenizers, huggingface_hub plus explicit torch/torchvision/torchaudio excludes. requirements.txt pins ctranslate2>=4.4.0,<5.0 (CTranslate2 4.x broke faster-whisper in Oct 2024 per research brief). Bundle size grew from 60 MB → 130 MB zipped (331 MB extracted). Research: research/Kaira v1.3 — faster-whisper Local Fallback Implementation-Ready Research Brief.md. | FILES: kaira.py, kaira.spec, requirements.txt, CHANGELOG.txt | RELEASED: no

[2026-04-18] CHANGE: v1.2.0 hotfix — fail-fast OpenAI client, tightened retry predicate, dead-letter journal. Three fixes that eliminate the failure-mode amplification discovered during the Apr-17 Rain-LTE outage (research/v1.2-incident-postmortem-2026-04-17.md). (1) OpenAI client now uses split httpx.Timeout(connect=10, write=45, read=60, pool=10) so stalled uploads die in ~45s instead of the SDK's 600s default (Cloudflare kills at ~100s anyway); max_retries=0 makes tenacity the sole retry owner, eliminating the stacked-retry bug where one failed upload could spawn up to 9 attempts over 20 minutes. (2) Tenacity predicate tightened to retry only on APIConnectionError, APITimeoutError, httpx.ConnectError/ReadTimeout/WriteTimeout/ConnectTimeout, and APIStatusError with status_code in {408, 429, 500, 502, 503, 504} — narrow transient set per research. Auth errors, bad-request 4xx, and permanent failures now fail fast instead of burning the 3-attempt budget. stop_after_attempt(3) + wait_random_exponential(multiplier=1, min=1, max=8) unchanged (3 attempts matches mobile-network research recommendation; 2 was too brittle, 5+ too slow). (3) Dead-letter journal: every pending_transcriptions.json entry now carries attempt_count, last_attempt_at, last_error_code, last_error_message, state (pending/retry_scheduled/dead_letter), retryable, next_retry_at, failure_class. attempt_count increments ONLY when a real execution attempt starts — not on queue-add, user-cancel, precondition-failure, or startup-scan enumeration (per research "failures that should not count"). After 3 counted failures OR a non-retryable error (auth, bad file), the entry promotes to dead_letter. journal_pending() excludes dead-letter — fixes the infinite-loop defect where the same poisoned file was re-prompted on every launch. New tray menu item "Failed recordings (N)" appears only when count > 0, opens the FailedRecordingsDialog with per-entry Retry / Reveal file / Delete actions. Dead-letter retention default 30 days (configurable 7/30/90/never via settings.json journal_retention_days). Manual Retry resets attempt_count to 0 so the user gets a fresh 3-attempt budget after fixing the underlying issue. Journal schema migration in _journal_load preserves legacy `attempts` field. Research: research/Kaira v1.3 Research Recommendations.md (§OpenAI client config, §Persistent queue and retry exhaustion). | FILES: voice_dictation.py, requirements.txt, CHANGELOG.txt | RELEASED: no

[2026-04-16] CHANGE: VAD hallucination guard + exponential-backoff retry + crash-recovery journal + outage toast. Complete rewrite of the transcription pipeline around a 3-layer defence against Whisper hallucinating phrases like "Thank you for watching" on silent recordings. Layer 1 = RMS energy pre-gate (0.005 floor, ~0.1ms) catches true silence like accidental hotkey taps. Layer 2 = Silero VAD via silero-vad-lite (ONNX, 2MB, zero Python deps, pinned to v0.2.1), peak-score check with threshold 0.30 and min 2 consecutive chunks — rejects near-silence / ambient noise that slipped past RMS. Layer 3 = 20-phrase hallucination blocklist at Whisper output (exact-match, case-insensitive) — "thank you for watching", "subscribe to my channel", sentinel "[SILENCE]", single-period, single "you", etc. Duration bypass: recordings <500ms or >10s skip the gate entirely (too short to classify / too long to be accidental). Silero warmup at boot on a background thread so first user dictation hits a warm model (first call is 5-15x slower than subsequent). VAD enabled/disabled via Preferences > Silence Filter checkbox; other tuning values (threshold, RMS floor, chunk count) persist in settings.json for power users. Full diagnostic logging of RMS, peak score, chunks-above-threshold, and decision for every recording. Whisper call parameters hardened: temperature=0, explicit language="en", sentinel initial_prompt instructing model to return [SILENCE] on empty audio. Retry layer uses tenacity with wait_random_exponential (1-8s min/max, 3 attempts total, ~12s cap) — differentiates transient errors (429, 5xx, timeouts, connection errors) from fatal ones (401 auth, 400 bad-request). Crash-recovery journal at %APPDATA%\Kaira\pending_transcriptions.json: every WAV is registered BEFORE the API call and removed only on successful paste, so crash/reboot mid-transcription loses nothing. When all 3 Whisper retries fail, widget emits transcription_failed signal → tray shows clickable outage toast ("OpenAI is unavailable — click to retry") that re-runs the same pipeline on messageClicked. On boot, _offer_startup_retries() scans the journal (pruning entries over 7 days old and for missing WAVs), shows a tray toast if any remain, and retries all of them on click. Same pipeline applies to command mode (transcribe voice command on selected text). Research basis: "Kaira v1.2 — Silero VAD False-Negative Risk Analysis & Threshold Calibration.md" + "Kaira v1.2 — Feature Research OpenAI Outage Toast + Retry & VAD Hallucination Guard.md". | FILES: voice_dictation.py, requirements.txt, CHANGELOG.txt | RELEASED: no

[2026-04-16] CHANGE: Hotkey conflict prevention — four-layer defence against the "intermediate-state triggers simpler combo" problem identified during v1.2 hold-to-talk testing.
